# Кэш и история расшифровок

Камертон держит готовый ответ в памяти сервиса в течение 60 минут после первого успешного распознавания. Повтор не продлевает срок. При заполнении кэша удаляются самые старые записи. Перезапуск сервиса очищает кэш.

- Лимит полезных данных составляет 32 МиБ и 256 записей, до 2 МиБ на одну запись. Память Python для служебных объектов и текущих запросов учитывается отдельно. Кэш содержит текст и метаданные результата.
- Для обычного PCM WAV проверяются точные отсчеты, частота, разрядность и число каналов. Другое имя или служебный блок WAV не мешают повторному использованию результата. Для остальных форматов проверяются байты файла, расширение и тип. Перекодирование с потерями и изменение звука могут дать разные ключи.
- Модель, ее эффективные настройки, глоссарий и поля запроса влияют на ключ. Внешние Bearer-ключи изолированы друг от друга. Веб-диктовка доступна владельцу или локальному клиенту с настроенным ключом.
- Файловый POST /v1/audio/transcriptions сообщает HIT, MISS или BYPASS в заголовке X-Kamerton-Cache. Для явно указанной модели попадание возможно до ее запуска. Потоковые ответы и ошибки не сохраняются. Кэш работает внутри Камертона, HTTP-ответы помечаются Cache-Control: no-store.
- В "Статусе сервиса" видны размер кэша, число попаданий и срок хранения. В замеры распознавания входят обработанные движком запросы. Таймер на попадании в кэш показывает задержку текущего ответа.

Десять минут несжатого WAV mono 16 кГц / 16 bit занимают около 18,3 МиБ. Текст из 1 500 слов обычно занимает десятки КиБ. Размер результата со спикерами и временными отметками зависит от числа сегментов. Байты файла все равно передаются на сервер и проверяются при повторной загрузке.

История вкладки "Диктовка" хранится в текущем браузере. В "Настройках" можно отключить ее или выбрать срок хранения. История содержит текст, имя файла и метаданные результата. Записи внешних клиентов в нее не попадают.

На сервере в изолированном контейнере Whisper Tiny обработал синтетический фрагмент длительностью 3 с за 1,442 с с запуском движка. Повтор того же WAV под другим именем занял 0,002 с на локальном HTTP и добавил одно попадание в кэш. Этот замер не включает передачу аудио по внешней сети.

## Проверка GigaAM v4 и Multilingual v2

В локальном Docker прогретые модели получили один и тот же PCM WAV длительностью 13,4 с. В повторе изменили имя и служебный блок WAV, сохранив отсчеты. Время измерено на стороне клиента по локальному HTTP.

| Модель | API, первый запрос | API, повтор | Диктовка, первый запрос | Диктовка, повтор |
| --- | ---: | ---: | ---: | ---: |
| GigaAM v4 RNN-T | 1,175 с | 0,014 с | 0,821 с | 0,002 с |
| GigaAM Multilingual v2 RNN-T | 2,331 с | 0,014 с | 2,084 с | 0,002 с |

В API получены `MISS` и `HIT`, в веб-диктовке поле `cached` изменилось с `false` на `true`. Смена языка создала отдельную запись. Повтор API-запроса к v4 после запуска Multilingual v2 вернулся из кэша без переключения модели. Пять результатов заняли 4854 байта без учета служебных объектов Python.

Документация по [хэшированию отсчетов в FFmpeg](https://ffmpeg.org/ffmpeg-formats.html), [структуре результата распознавания](https://docs.aws.amazon.com/transcribe/latest/dg/how-input.html) и [HTTP-кэшированию](https://www.rfc-editor.org/rfc/rfc9111.html).
