# Дополнительные движки Камертона

В `.env` задайте `KAMERTON_BUILD_TARGET=multiengine` и пересоберите сервис той же
командой Compose, которой развернут текущий профиль. Для локального профиля нужны
оба манифеста.

```sh
docker compose -f docker-compose.yml -f docker-compose.local.yml up -d --build
```

Дополнительные модели появятся в каталоге. Камертон загружает веса выбранной
модели по требованию и сверяет размер и SHA-256. Стандартная сборка по умолчанию
содержит только GigaSTT.

| Модели | Движок | Обработка файлов |
|---|---|---|
| Whisper Tiny, Small, Large V3 Q5_0, Large V3 Turbo Q5_0 | whisper.cpp, CPU | Многоязычное распознавание. Язык можно указать в запросе. |
| Parakeet TDT 0.6B V3 Q8_0, Moondream Parakeet Ultra Q8_0 | parakeet.cpp, CPU | Паузы определяются Silero VAD. Длинный файл обрабатывается фрагментами до 30 с. |
| Nemotron 3.5 ASR Streaming 0.6B Q8_0 | parakeet.cpp, CPU | Внутреннее потоковое состояние сохраняется между частями файла. |
| T-one | sherpa-onnx и RuPunct Small INT8, CPU | Русская модель для телефонного звука. Пунктуация и регистр восстанавливаются отдельным локальным проходом. |
| GigaAM v4 RNN-T | PyTorch, CPU, профиль `gigaam-v4` | Русский и английский. Для записей длиннее 30 с встроенный VAD делит аудио на фрагменты до 30 с. |
| GigaAM v4 CTC | PyTorch, CPU, профиль `gigaam-v4` | Посимвольное распознавание русской и английской речи, E2E-оформление и тот же VAD для длинных записей. |
| GigaAM Multilingual v2 RNN-T | PyTorch, CPU, профиль `gigaam-v4` | 21 язык. Автоопределение или код языка в поле `language` запроса. Длинные файлы обрабатываются с VAD. |

### GigaAM v4

Для Linux x86-64 задайте `KAMERTON_BUILD_TARGET=gigaam-v4` и пересоберите Compose. Этот образ включает модели профиля `multiengine` и отдельное окружение Python для v4. В группе GigaAM можно выбрать RNN-T (469 МиБ, API ID `gigaam-v4-rnnt`) или CTC (456 МиБ, API ID `gigaam-v4-ctc`). При первом развертывании Камертон скачает комплект выбранной модели с Hugging Face и проверит SHA-256 каждого файла. [Ревизия CTC](https://huggingface.co/ai-sage/GigaAM-v4/tree/5b81216afa29c8b5a1a3e64c424c8416e18c1e5b)

В проверенной локальной сборке x86-64 образ с окружением v4 весит примерно на 1,38 ГиБ больше `multiengine`. Веса модели занимают отдельное место в томе моделей.

Ревизия `180301a192bb45bc2b2ca122e0d4aab24ffe7a96` содержит энкодер Zapformer, две головы RNN-T и два токенизатора. Сервис возвращает форматированный результат E2E и поддерживает временные отметки слов. VAD для длинных записей загружается из того же комплекта весов. Распознавание запускается локально на CPU в дочернем процессе. Для файлового API действуют общие ограничения размера и длительности. Глоссарий и диаризация для этой модели недоступны. [Модель и исходный код](https://huggingface.co/ai-sage/GigaAM-v4/tree/180301a192bb45bc2b2ca122e0d4aab24ffe7a96)

GigaSTT 2.22.0 загружает подготовленные ONNX-графы v3. Экспорт v4, который описывает автор, создает другой набор графов для двух голов. Для v4 используется авторский инференс с `safetensors`. Локальное окружение Python можно указать через `GIGAAM_V4_PYTHON`. Ему нужны зависимости из `requirements.txt` и `requirements-gigaam-v4.txt`, а также `ffmpeg` в `PATH`. [Замеры и условия проверки](research/gigaam-v4.md)

### GigaAM Multilingual v2

В том же Docker-профиле доступна "GigaAM Multilingual v2 RNN-T". ID для API - `gigaam-multilingual-v2-rnnt`. Комплект весит около 1,47 ГиБ. При выборе языка, например `language=kk`, модель использует соответствующий языковой код и на коротких, и на длинных файлах. По умолчанию используется автоопределение. Текст возвращается с пунктуацией и нормализацией чисел. [Ревизия весов и код](https://huggingface.co/ai-sage/GigaAM-Multilingual-v2/tree/c9d7aee4afe99fcc50064ac3ebab35d7db6fbc36)

В релизе v2 распознавание выполняет RNN-T. Модели "GigaAM Multilingual CTC" и "GigaAM Multilingual CTC Large" относятся к первому Multilingual и работают через GigaSTT. Ветки `ssl` у v4 и Multilingual v2 содержат базовые энкодеры для дообучения, без ASR-декодера. Поэтому у них нет ID для запросов на транскрибацию. [Варианты Multilingual v2](https://huggingface.co/api/models/ai-sage/GigaAM-Multilingual-v2/refs) · [Варианты первого Multilingual](https://huggingface.co/ai-sage/GigaAM-Multilingual)

Загрузка занимает до `MAX_UPLOAD_MB` и до 30 минут декодированного аудио для
дополнительных движков. Для GigaSTT действуют его штатные пределы. При сравнении
модели запускаются по очереди. Если выбран дополнительный движок, остановите
текущую рабочую модель в разделе состояния. `COMPARE_SINGLE_ENGINE=true`
применяет это правило и к сравнениям двух моделей GigaSTT.

В разделе "Модели" кнопка "Настроить запуск" открывает параметры выбранного
движка. После успешного запуска Камертон сохраняет их для этой модели и использует
при следующем запуске из веб-консоли или по ID в API.

| Движок | Параметры запуска |
|---|---|
| Whisper | Потоки CPU и ширина поиска (`--threads`, `--beam-size`). |
| Parakeet TDT и Ultra | Максимальная длина фрагмента Silero VAD от 5 до 30 с. |
| Nemotron ASR | Русский, английский или автоопределение языка. Язык из запроса имеет приоритет. |
| T-one | Потоки CPU и дополнительная пунктуация с восстановлением регистра. При отключении этого прохода возвращается исходный текст модели. Отдельной нормализации чисел в этой связке нет. |
| GigaAM v4 RNN-T, v4 CTC и Multilingual v2 RNN-T | Потоки CPU. Модели возвращают E2E-текст со встроенной пунктуацией и нормализацией. |

Пустое поле числа потоков Whisper и T-one использует `ALTERNATE_THREADS`
(по умолчанию 3). Parakeet.cpp использует штатное число потоков в рамках
выделенного CPU контейнера. Сравнение продолжает запускать модели по заданным
для него условиям. [Параметры Whisper](https://github.com/ggml-org/whisper.cpp/blob/master/examples/server/server.cpp) ·
[Параметры C API parakeet.cpp](https://github.com/mudler/parakeet.cpp/blob/01abde80dd018570f7590bf59fcb46a495e8c0c2/include/parakeet_capi.h) ·
[Параллельность в parakeet.cpp](https://github.com/mudler/parakeet.cpp/blob/01abde80dd018570f7590bf59fcb46a495e8c0c2/docs/concurrency.md)

При запуске дополнительных движков Камертон выбирает свободный порт на loopback.
В нагруженном сценарии проверено, что Whisper может не занять только что
освобожденный порт GigaSTT. Раздельные порты позволяют завершить один процесс и
сразу запустить другой. Клиенты продолжают обращаться к тому же API Камертона.

## Глоссарий и технические логи

GigaAM через GigaSTT подставляет фразы при декодировании. Консоль проверяет их
по словарю установленной модели, учитывая доступные символы и токены.

Whisper получает сохраненные фразы как начальный текстовый контекст. В подсказку
входит до 220 байт UTF-8 целых фраз. Вес 0 или меньше выключает фразу. Явный `prompt`
клиента имеет приоритет. Пустой `prompt` или `max_context=0` отключает подстановку
для этого запроса. На синтетическом фрагменте с двумя именами Whisper Tiny из
поставляемого образа записал оба имени по подсказке. Следующий запрос без подсказки
вернул исходный вариант написания. [HTTP-поля whisper.cpp](https://github.com/ggml-org/whisper.cpp/blob/master/examples/server/server.cpp#L499-L579)

Интерфейс показывает, что глоссарий недоступен для Parakeet, Nemotron ASR и T-one.
Зафиксированный C-интерфейс parakeet.cpp дает выбор языка для Nemotron и доступ
к логитам моделей с CTC. Подсказки sherpa-onnx работают с трансдьюсерами, а здесь
T-one использует CTC. [C-интерфейс parakeet.cpp](https://github.com/mudler/parakeet.cpp/blob/01abde80dd018570f7590bf59fcb46a495e8c0c2/include/parakeet_capi.h) · [Подсказки sherpa-onnx](https://k2-fsa.github.io/sherpa/onnx/hotwords/index.html)

Технические логи показывают диагностику запуска Whisper, Parakeet, Nemotron ASR
и T-one с именем модели. После готовности Камертон фиксирует события жизненного
цикла процесса. Сторонние движки могут печатать текст запроса или расшифровки
при обработке, поэтому их вывод в этот период читается и отбрасывается.

## Разметка говорящих

На странице диктовки выберите файл и включите "Разметить говорящих". Опция
доступна для Parakeet, Nemotron ASR и T-one. При первом использовании консоль
отдельно скачает около 191 МиБ весов Nemotron-3 Diarization. Обычное распознавание
работает без этих весов. Модель возвращает временную шкалу активности, включая
перекрытия, а распознанные слова помечаются по максимальному пересечению по времени.

Для клиента OpenAI-совместимого API используется `response_format=diarized_json`.
Скачивание выполняет владелец в веб-консоли. Поля `segments` содержат реплики с
временем и условными метками говорящих, `speaker_segments` - шкалу активности.
Метки относятся к одной записи.

Проверка на Linux CPU в изолированном контейнере с одним выделенным CPU.
На тишине меток не появилось. На контрольных файлах получены один говорящий
и два говорящих с перекрытием. На синтетическом файле 28,5 с при допуске 250 мс
расхождение составило 18,3% размеченного времени говорящих. Все расхождения
относились к пропущенному времени речи. Разметка задавалась по расположению
синтезированных реплик, поэтому паузы внутри реплики влияют на оценку.
Обработка файла заняла 12,55 с с разметкой и 11,85 с при обычном распознавании.
Пик контейнера за серию составил 2111 МиБ. На открытом файле 23,6 с найдены
два говорящих и пять интервалов. [Контрольный файл parakeet.cpp](https://github.com/mudler/parakeet.cpp/blob/01abde80dd018570f7590bf59fcb46a495e8c0c2/tests/fixtures/two_speakers.wav)

## Место на диске

Каталог показывает ожидаемый размер весов и фактический размер скачанных файлов.
В состоянии сервиса отдельно видны модели, данные, корневая файловая система
контейнера и свободное место на диске моделей. Значения обновляются до одного
раза в 30 секунд. Корневая файловая система учитывает видимое содержимое образа
и записанные поверх него файлы. При недоступных для чтения каталогах консоль
показывает нижнюю оценку. Для оценки пространства, которое Docker может
освободить на хосте, используйте `docker system df`.

В проверенной сборке Linux amd64 Docker показал 336 МБ для стандартного образа
и 1,29 ГБ для расширенного. Веса хранятся в отдельном томе и в эти цифры не входят.

## Проверка диаризации на сервере

В изолированном контейнере с тремя CPU Parakeet Ultra и Nemotron-3 Diarization обработали 43,6 с синтетической речи за 15,1 с. Для четырех очередующихся реплик двух голосов доминирующие метки совпали с порядком A-B-A-B. На выходе 9 сегментов. Пиковое потребление памяти контейнера составило 1 429 МиБ. Готовый ответ с текстом и метками занял 2 678 байт кэша.

Проверка покрывает последовательную речь, этапы интерфейса и повторную выдачу готового результата. Качество на живых записях и перекрывающейся речи этим замером не оценивалось.
